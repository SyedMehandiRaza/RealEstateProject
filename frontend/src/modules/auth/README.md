# auth module (frontend)

- `store/authSlice.js`: access token + current user (memory only)
- `pages/`: one folder per Figma frame (built with `/figma-to-module auth <page>`)
  - `LoginPage` (TASK-033): label "Email" (DEC-022), `loginSchema`; success stores `{ accessToken, user }` in the auth slice and opens `landingPathFor(user)`; any other error (401 `invalidCredentials`, 429, ...) shows the API message in the form alert; 403 `EMAIL_NOT_VERIFIED` opens Verify with `{ email }` in the router state; `state: { passwordChanged: true }` (from Reset password, TASK-036) shows `authMessages.api.passwordChanged`. Google / Apple hidden (DEC-021)
  - `SignUpPage` (TASK-034): Buyer / Developers tabs (`/sign-up`, `/sign-up?role=developer`), `signUpSchema`; success opens Verify with `{ email }` in the router state
  - `ForgotPasswordPage` (TASK-036): `forgotPasswordSchema`, copy "email address" (DEC-022); every accepted email opens the reset Verify with `{ email }` in the router state (the API answers 200 for unknown emails too); shows `state.resetError` from Reset password in the form alert
  - `VerifyResetCodePage` (TASK-036): `VerifyCodeScreen` with `verifyResetCode` / `resendResetCode`; redirects to Forgot Password without an email; on success replaces itself with Reset password and `{ resetToken }` in the router state
  - `ResetPasswordPage` (TASK-036): `resetPasswordSchema`; the reset token lives only in the router state (not Redux, browser storage or the URL); success replaces the entry with Log in and `state: { passwordChanged: true }`; a missing token, a 401 or a `resetToken` field error goes back to Forgot Password with `{ resetError }`
  - `SelectCountryPage` (TASK-035): Buyer only (ProtectedRoute); four `CountryOption`s in a radiogroup from `COUNTRY_CODES`, `selectCountrySchema`; the saved `preferredCountryCode` starts selected; success replaces the user in the auth slice (keeping the current access token) and opens `afterCountrySelectedPath(user)` (`/` until Q-034); 403 and other API errors show in the form alert, a `countryCode` field error under the list
  - `ProfessionalInfoPage` (TASK-038): Developer only (ProtectedRoute); `professionalInfoSchema`; Type of Developer and Experience Level are `Select`s (Controller) whose values are `DEVELOPER_TYPES` / `EXPERIENCE_LEVELS` with the Figma labels; Company Name keeps the Figma "(optional)" label and the schema refine shows `companyName.required` for a Company; an empty Company Name is not sent; success (`{ profile }`) pushes Upload Document; field errors from the API under their field, anything else (403, an Active refusal while Q-033 is open) in the form alert
  - `UploadDocumentsPage` (TASK-039): Developer only (ProtectedRoute); one `DocumentSlot` per kind that GET `/auth/me/verification` lists with no document or a rejected one (Company 3, Individual 2, DEC-022; the developer type comes only from that list); each picked file is checked with `documentUploadSchema` before it is shown (Profile Photo JPG/PNG, 10 MB); the Government ID type is checked at Next; x removes a file in the browser only; Next (disabled until every slot has a file) sends one multipart POST `/auth/me/documents` (file parts named after the kind, plus `idDocumentType`) and replaces itself with the status route; `fields["documents.<kind>.<field>"]` shown on the slot (`idDocumentType` under the Select), 409 and anything else in the form alert; nothing left to upload opens the status route
  - `VerificationStatusPage` (TASK-040): Developer only (ProtectedRoute); `/developer/status` shows Pending, Approved or Reject from GET `/auth/me/verification` (cached, e.g. from Upload's submit): headline from `verificationOutcome(documents)` (any rejected → Verification Unsuccessful, all approved → Your Account is Active!, otherwise Under Review; DEC-022), every required document as an UploadedFileCard with its StatusBadge (name `fileName`, else the kind label; size `sizeBytes`, the size line hidden without it, TASK-047), and under each rejected one "Reject reason: <reason as written>". A required kind with `status: null` opens Upload Document instead. Buttons: Pending "Back to login" = POST `/auth/logout`, clear the auth slice and RTK Query cache, replace with Log in (smallest safe choice while Q-034 is open); Approved "View plan" opens `/developer/plans` ("Plans coming soon" placeholder, DEC-022); Reject "Resubmit Documents" opens Upload Document (which offers only the rejected or missing kinds)
  - `VerifyEmailPage` (TASK-034): reads `email` from the router state (redirects to Sign up without it); on success stores `{ accessToken, user }` in the auth slice and opens Professional info (developer) or Select a country (buyer)
- `components/`, `hooks/`: module-specific pieces
  - `hooks/verificationOutcome.js`: `verificationOutcome(documents)` → `unsuccessful` | `active` | `under_review` (TASK-040)
  - `hooks/landingPath.js`: `landingPathFor(user)`, where Log in and Verify email send the Account (Developer: Professional info, otherwise Select a country). `afterCountrySelectedPath(user)` (TASK-035), where Select a country sends the Buyer (`/`). Placeholders until Q-034; TASK-041 replaces both
  - `DocumentSlot` (TASK-039): label or Government ID type Select, then FileDropzone or UploadedFileCard (x), with the slot's file message
  - `VerifyCodeScreen`: the Verify frame (OTP form, `verifyCodeSchema`, Resend); takes `email`, `verify`, `resend`, `onVerified`, so the password-reset Verify (TASK-036) reuses it with its own mutations
- `api/authApi.js`: `baseApi.injectEndpoints(...)`; each page ticket adds its endpoints (TASK-033: `login`; TASK-034: `signUp`, `verifyEmail`, `resendVerification`; TASK-036: `forgotPassword`, `verifyResetCode`, `resendResetCode`, `resetPassword`; TASK-035: `selectCountry` (PUT `/auth/me/country`); TASK-038: `saveProfessionalProfile` (PUT `/auth/me/professional-profile`); TASK-039: `getVerification` (GET `/auth/me/verification`) and `submitDocuments` (POST `/auth/me/documents`, FormData; its `verification` replaces the cached GET); TASK-040: `logout` (POST `/auth/logout`, 204); each returning the response `data`)
- `routes.jsx`: `AUTH_PATHS` and `authRoutes` (spread into `app/routes.jsx`); routes point at `AuthPlaceholderPage` until their page ticket replaces them
- Shared UI used by the pages: `components/ui/` AuthSplitLayout (`icon` slot above the heading, used by the status screens, TASK-047), TextInput, Button, Tabs, OtpInput (TASK-031), CountryOption (TASK-032)
