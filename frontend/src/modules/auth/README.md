# auth module (frontend)

- `store/authSlice.js`: access token + current user (memory only), and `restoringSession` while the app-start refresh runs
- `api/restoreSession.js` (TASK-049): `restoreSession(dispatch)`, called once in `main.jsx` before the first render: one POST `/auth/refresh` through baseApi's shared `refreshAccessToken` (one per tab, inside the `auth-refresh` Web Lock), so a reload keeps the session. While it runs, `ProtectedRoute` shows a blank `role="status"` ("Loading") instead of redirecting; public pages render at once. A failed refresh (401, network) leaves the user logged out with no message; a login that finished meanwhile is kept
- `pages/`: one folder per Figma frame (built with `/figma-to-module auth <page>`)
  - `LoginPage` (TASK-033): label "Email" (DEC-022), `loginSchema`; success stores `{ accessToken, user }` in the auth slice and opens the landing path (`useLandingPath`, TASK-041; Log In stays disabled while it loads); any other error (401 `invalidCredentials`, 429, ...) shows the API message in the form alert; 403 `EMAIL_NOT_VERIFIED` opens Verify with `{ email }` in the router state; `state: { passwordChanged: true }` (from Reset password, TASK-036) shows `authMessages.api.passwordChanged`. Google / Apple hidden (DEC-021)
  - `SignUpPage` (TASK-034): Buyer / Developers tabs (`/sign-up`, `/sign-up?role=developer`), `signUpSchema`; success opens Verify with `{ email }` in the router state
  - `ForgotPasswordPage` (TASK-036): `forgotPasswordSchema`, copy "email address" (DEC-022); every accepted email opens the reset Verify with `{ email }` in the router state (the API answers 200 for unknown emails too); shows `state.resetError` from Reset password in the form alert
  - `VerifyResetCodePage` (TASK-036): `VerifyCodeScreen` with `verifyResetCode` / `resendResetCode`; redirects to Forgot Password without an email; on success replaces itself with Reset password and `{ resetToken }` in the router state
  - `ResetPasswordPage` (TASK-036): `resetPasswordSchema`; the reset token lives only in the router state (not Redux, browser storage or the URL); success replaces the entry with Log in and `state: { passwordChanged: true }`; a missing token, a 401 or a `resetToken` field error goes back to Forgot Password with `{ resetError }`
  - `SelectCountryPage` (TASK-035): Buyer only (ProtectedRoute); four `CountryOption`s in a radiogroup from `COUNTRY_CODES`, `selectCountrySchema`; the saved `preferredCountryCode` starts selected; success replaces the user in the auth slice (keeping the current access token) and opens the landing path (home once a country is saved, TASK-041); 403 and other API errors show in the form alert, a `countryCode` field error under the list
  - `ProfessionalInfoPage` (TASK-038): Developer only (ProtectedRoute); `professionalInfoSchema`; Type of Developer and Experience Level are `Select`s (Controller) whose values are `DEVELOPER_TYPES` / `EXPERIENCE_LEVELS` with the Figma labels; Company Name keeps the Figma "(optional)" label and the schema refine shows `companyName.required` for a Company; an empty Company Name is not sent; success (`{ profile }`) pushes Upload Document; field errors from the API under their field, anything else (403, an Active refusal while Q-033 is open) in the form alert
  - `UploadDocumentsPage` (TASK-039): Developer only (ProtectedRoute); one `DocumentSlot` per kind that GET `/auth/me/verification` lists with no document or a rejected one (Company 3, Individual 2, DEC-022; the developer type comes only from that list); each picked file is checked with `documentUploadSchema` before it is shown (Profile Photo JPG/PNG, 10 MB); the Government ID type is checked at Next; x removes a file in the browser only; a 403 from the GET (no Professional info yet) opens Professional info (OnboardingGuard, TASK-041), other GET errors show in the form alert; Next (disabled until every slot has a file) sends one multipart POST `/auth/me/documents` (file parts named after the kind, plus `idDocumentType`) and replaces itself with the status route; `fields["documents.<kind>.<field>"]` shown on the slot (`idDocumentType` under the Select), 409 and anything else in the form alert; nothing left to upload opens the status route
  - `VerificationStatusPage` (TASK-040): Developer only (ProtectedRoute); `/developer/status` shows Pending, Approved or Reject from GET `/auth/me/verification` (cached, e.g. from Upload's submit): headline from the response `status` (`under_review` → Under Review, `active` → Your Account is Active!, `unsuccessful` → Verification Unsuccessful; the backend owns the rule, DEC-033/DEC-035; TASK-049 removed the frontend copy; an unknown value shows Under Review), every required document as an UploadedFileCard with its StatusBadge (name `fileName`, else the kind label; size `sizeBytes`, the size line hidden without it, TASK-047), and under each rejected one "Reject reason: <reason as written>". A required kind with `status: null` opens Upload Document and a 403 opens Professional info (OnboardingGuard, TASK-041); other GET errors show as returned. Buttons: Pending "Back to login" = POST `/auth/logout`, clear the auth slice and RTK Query cache, replace with Log in (kept by TASK-041); Approved "View plan" opens `/developer/plans` ("Plans coming soon" placeholder, DEC-022); Reject "Resubmit Documents" opens Upload Document (which offers only the rejected or missing kinds)
  - `VerifyEmailPage` (TASK-034): reads `email` from the router state (redirects to Sign up without it); on success stores `{ accessToken, user }` in the auth slice and opens the landing path (`useLandingPath`, TASK-041; Verify stays disabled while it loads)
- `components/`, `hooks/`: module-specific pieces
  - `hooks/landing.js` (TASK-041, Q-034, DEC-039): the one landing rule, "resume onboarding at the first unfinished step". Developer (and a dual-role Account) until Active: Professional info (GET `/auth/me/verification` 403), then Upload Document (an entry with `status: null`, or no entries), then the status screen; Active (`user.developerVerificationStatus` or the GET `status`) hands over to the Buyer rule: Select a country while no `preferredCountryCode`, else home `/`. `landingPath(user, verification)` is the pure rule; `useLandingPath()` resolves it after Log in, Verify email and Select a country (one fresh GET, not kept subscribed, only while the developer flow is open; a non-403 failure opens the status screen, which shows it); `outOfOrderRedirect(page, user, verification)` sends only a later step to the first unfinished one (Professional info stays editable until Active, Q-033; a Buyer can change the country; Approved still shows on the status screen)
  - `components/OnboardingGuard.jsx` (TASK-041): wraps Select a country, Upload Document and the status screen in `routes.jsx` (Professional info, the first step, is never out of order) (inside ProtectedRoute, so it also runs after the reload session restore) and applies `outOfOrderRedirect`. Upload Document and the status screen render while the GET loads (their own loading state); Select a country shows a blank `role="status"` until it is known, so a dual-role Account in the developer flow never sees it flash. `getVerification` provides the `Verification` tag and `saveProfessionalProfile` invalidates it, so the 403 cached at Log in is dropped once the profile exists - `DocumentSlot` (TASK-039): label or Government ID type Select, then FileDropzone or UploadedFileCard (x), with the slot's file message
  - `VerifyCodeScreen`: the Verify frame (OTP form, `verifyCodeSchema`, Resend); takes `email`, `verify`, `resend`, `onVerified`, so the password-reset Verify (TASK-036) reuses it with its own mutations
- `api/authApi.js`: `baseApi.injectEndpoints(...)`; each page ticket adds its endpoints (TASK-033: `login`; TASK-034: `signUp`, `verifyEmail`, `resendVerification`; TASK-036: `forgotPassword`, `verifyResetCode`, `resendResetCode`, `resetPassword`; TASK-035: `selectCountry` (PUT `/auth/me/country`); TASK-038: `saveProfessionalProfile` (PUT `/auth/me/professional-profile`); TASK-039: `getVerification` (GET `/auth/me/verification`) and `submitDocuments` (POST `/auth/me/documents`, FormData; its `verification` replaces the cached GET); TASK-040: `logout` (POST `/auth/logout`, 204); each returning the response `data`)
- `routes.jsx`: `AUTH_PATHS` and `authRoutes` (spread into `app/routes.jsx`); routes point at `AuthPlaceholderPage` until their page ticket replaces them
- Shared UI used by the pages: `components/ui/` AuthSplitLayout (`icon` slot above the heading, used by the status screens, TASK-047), TextInput, Button, Tabs, OtpInput (TASK-031), CountryOption (TASK-032)
