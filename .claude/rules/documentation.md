# Documentation Rules

- Keep setup instructions accurate and runnable.
- Record confirmed requirements in `docs/REQUIREMENTS.md` or the relevant module spec.
- Record important decisions, alternatives, and rationale in `docs/DECISIONS.md`.
- Keep architecture and dependency documentation current when structure changes.
- Document API contracts, schema changes, environment variables (names only, never values), and operational steps where relevant.
- Separate confirmed facts from assumptions and unresolved questions.
- Prefer updating existing documents over creating duplicate sources of truth.
- Do not claim documentation is complete if relevant sections remain unknown.
